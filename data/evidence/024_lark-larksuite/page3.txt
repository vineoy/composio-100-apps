OpenAPI MCP Tool (hereinafter referred to as "MCP Tool") can help you quickly integrate AI agents with Lark's open capabilities, enabling automated scenarios such as document processing, conversation management, and calendar scheduling based on agents.

## Features

The MCP Tool uses the MCP (Model Context Protocol) protocol to connect with the Lark Open Platform, providing a rich set of OpenAPI tools that cover Lark's core functions (such as messages, groups, calendars, Base apps, etc.). It also supports application access tokens (tenant_access_token) and user access tokens (user_access_token) to ensure secure and controllable API calls. The features of the MCP Tool are as follows:

*   Provides a simple and easy-to-use command line interface for quick configuration and startup.
*   Supports various configuration methods, adapting to different usage scenarios.
*   Seamlessly integrates with mainstream AI tools (such as Trae, Cursor, Claude).
*   After configuring the application information, the application access credentials can be obtained automatically; after logging into the MCP and completing user authentication, the user access credentials can be obtained automatically, with support for automatic refresh.

## Supported openAPI

You can check [tools](https://github.com/larksuite/lark-openapi-mcp/tree/main/docs) to get the list of OpenAPI supported by the MCP Tool on the Lark Open Platform. You can also determine if an API is supported within the MCP Tool through the API documentation. For example, open an API development document, such as [Send Message](https://open.larksuite.com/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/create). If there is a **"Try it out"** button, it indicates that the API is available within the MCP Tool.

*   APIs in grayscale (i.e., APIs marked as **Limited access** at the beginning of the API documentation) are temporarily not supported in the MCP tool.
*   APIs related to image or file upload/download are temporarily not supported within the MCP tool.

## MCP tool naming scheme

The MCP Tool follows the naming scheme of `biz.version.resource.method`, consistent with the method naming of the server-side Node SDK. You can obtain the name of an OpenAPI in the MCP Tool in the following way:

In the API documentation, click **Try it out** and check the **Node SDK** sample code. The function after the `client` method is the name of the API in the MCP Tool. For example, as shown in the figure below, the name of the Send Message API is `im.v1.message.create`.
