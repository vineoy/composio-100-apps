Connect AI assistants to Front via the MCP server
Front's MCP server (
mcp.frontapp.com/mcp
) lets AI agents act on Front conversation data using a single OAuth-authenticated endpoint. Agents authenticate as a specific Front user, with permissions matching that user's role (user-scoped authorization). The MCP server is separate from the
Admin MCP server
, which manages Front configurations such as rules, setting up teammates, managing AI features, etc.
This article covers how to connect the MCP server to any MCP-compatible client to Front using an OAuth app you create yourself in the Front developer settings. For the user-facing overview, official directory listings (Claude, and others coming), and use case inspirations for Front teammates, see the general
Help Center article on the MCP server
.
Looking for examples before you build?
The
MCP space in the Front Community
has workflow walkthroughs, sample prompts, and more. You can also start up discussions about the MCP server with fellow users and our team.

The identity model is the part most worth internalizing: the agent's effective permissions are exactly the authorizing teammate's permissions. If the teammate can't see an inbox, the agent can't either.

Use cases
A few patterns this surface unlocks:
Custom agent harnesses.
Wire Front into Claude Code, Cursor, or an in-house orchestrator alongside your other tools (GitHub, Notion, Jira, Slack, Linear, your CRM) for cross-system workflows: customer reports a bug, agent reproduces it, identifies the suspect PR, and posts an internal comment with the diagnosis.
Multi-tenant partner integrations.
Publish an OAuth app that any Front admin can install. Each end user authorizes individually.
Triage and routing agents.
Scheduled or event-driven agents that search the inbox, classify by topic, assign to the right teammate, and draft a first-pass reply for human review.
Conversation insights and enrichment.
Pull conversation data into your own pipelines for analysis, KB extraction, or feedback ingestion. The conversation timeline includes messages, comments, tags, assignment history, and more in a single stream.
Set up the MCP server connection
📘
Connect Claude and ChatGPT/Codex from the official directory
If you're using Claude or ChatGPT, we recommend you connect the Front MCP server from the official directories:
Claude official directory
ChatGPT official directory
If you install Claude or ChatGPT from the official directories, you do not need to complete either step in this section (
Set up the Front developer app with the Front MCP feature
or

To connect via an official directory:
A Front admin (or any user authorized to install integrations from the Front App Store) must connect via the directory links above.
Then, any user in your company can use the directory links to connect their own accounts.
Connecting an AI assistant to Front's MCP server has two general steps: create a Front developer app with the Front MCP feature, and then connect your AI client using the app's credentials.
👍
After you complete these two steps, your teammates will be able to find the Front MCP server in your AI assistant and connect to it without having to create a developer app or configure the connection details on the AI client side.

Tips for authorization
📘
Match your client's requested scopes to your OAuth app.
By default, many AI assistants (including Claude) will request every scope the MCP server supports. If those scopes exceed what you enabled on the Front developer app, the authorization flow may return an error.
If you encounter this error, configure your client to only request the scopes your app is set up for. In Claude, for example, this is set in the client's JSON config. See Claude's
docs on restricting OAuth scopes
for the exact syntax. Other clients have similar settings; check their documentation if you hit an authorization error.
When the client first connects, each user will be redirected to Front to log in and consent to the requested scopes. The resulting token is bound to that specific Front user and they can only act on data their Front role allows.
📘
A note on enterprise deployment:
If your AI assistant is centrally managed (e.g. Claude Enterprise, ChatGPT Enterprise), your IT team may need to allow the connection or distribute the app credentials. Each end user still completes the OAuth consent flow individually. This is how Front guarantees that every tool call has a real, attributable user behind it.
Getting access to new tools
When Front adds a tool that needs a permission your connection doesn't have yet, the tool appears in your AI assistant, but calling it returns a
missing required scopes
error. That's because a connection keeps the permissions that were approved when it was first authorized; it doesn't pick up new ones on its own.
What you need to do depends on how you connected.
📘
Connected from the Claude or ChatGPT directory
Front keeps the directory apps up to date, so there's nothing to change in Front. Each user disconnects Front in their AI assistant, connects it again, and approves the new permission on the consent screen.
📘
Connected with your own developer app
A Front admin opens your developer app (
Settings > Company > Developer
), opens its
Front MCP
feature, and enables the new permission under
Resource permissions
. The error message names the permission the tool needs.
Each user disconnects Front in their AI assistant and connects it again.
Until both steps are done, the new tool keeps returning the error. Other tools keep working.
Rate limits
The Front MCP server meters usage in tool calls per minute. Every tool costs the same, regardless of which one it is or how much data it returns. MCP server limits are independent of Core API limits. Tool calls never draw down your API rate limit, and API requests never draw down your MCP limit.
Limits by plan
📘
The limits are minimums rather than absolute ceilings
Capacity refills continuously instead of resetting on a fixed schedule, so unused capacity accumulates. If your agent has been idle or running below its limit, it can briefly exceed the numbers in the table before settling back.
Plan
Tools call per minute
Starter
100
Professional
200
Enterprise
300
Limits are keyed on the teammate connecting to the MCP server. Connecting additional MCP clients under the same teammate authorization neither increases nor divides the limit.
Capacity refills continuously rather than resetting on a fixed schedule, so short bursts above the stated rate are expected as long as your sustained usage stays below it.
Limits by developer apps
Unpublished apps in your company share a single pool, so adding more apps divides the available capacity rather than multiplying it. An app published in our App Store gets its own pool per install.
How to handle a limit
When you hit an MCP server rate limit, the server returns the rejection as a tool result rather than an HTTP error. The message tells your AI assistant how long to wait and, where one exists, points to a cheaper alternative tool.
The message also tells your assistant which limit it hit.
If it ran out of budget, your assistant needs to wait for capacity to refill.
If it hit a safety cap, your assistant needs to slow its request rate.
Every response carries your limit, remaining capacity, reset timing, and what the request cost. Wait the stated time before retrying. Earlier retries will simply be rejected again.
📘
If you need a rate limit increase, you can change your plan or purchase an add-on. For more details on plans and add-ons, visit our
Pricing
page.
AI agents
AI agents have their own separate limits. See
AI agents [Beta]
for details.

Troubleshooting
401 Unauthorized
on every request
The token is invalid, expired, or has been revoked. Common causes:
The user revoked the app's access in Front's connected apps settings.
A company admin uninstalled the OAuth app entirely.
The access token expired and the refresh flow didn't fire. Re-authenticate to mint a new token.
missing required scopes
on a tool
Your connection doesn't have a permission this tool needs. This usually happens after Front adds a tool. See
Getting access to new tools
.
A tool stops working after a user's Front access changes
A tool can also fail if the authenticated Front user lost access to the relevant inbox, team, or resource between authorization and the tool call. Permissions are enforced at call time against the user's current Front role.
429 Too Many Requests
If you're seeing rate-limit errors during normal operation, the most common cause is a polling loop that's tighter than it needs to be. Approval-by-polling loops should generally poll on the order of seconds-to-minutes, not sub-second. For more details, please see the
rate limits
section.
