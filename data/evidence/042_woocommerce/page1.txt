Introduction
​
WooCommerce registers product and order abilities in WordPress. With the MCP Adapter plugin, AI clients can discover and run these store operations through the Model Context Protocol (MCP), subject to WordPress and WooCommerce permissions.
info
Developer Preview Notice
The MCP implementation in WooCommerce is currently in developer preview. Implementation details, APIs, and integration patterns may change in future releases as the feature matures.
Enabling MCP Integration
​
WooCommerce always registers its abilities through the WordPress Abilities API; there is no WooCommerce setting to turn on. To make them available to MCP clients, install and activate the
MCP Adapter plugin
:
wp plugin install mcp-adapter --activate
WooCommerce does not bundle the MCP adapter.
Authentication and Security
​
WordPress Application Password Requirements
​
Remote HTTP connections authenticate using a WordPress username and an
Application Password
. Do not use your account password or a WooCommerce REST API key.
To create an Application Password:
In the WordPress dashboard, navigate to
Users → Profile
.
Under
Application Passwords
, enter a name for the MCP client.
Click
Add New Application Password
.
Copy the generated password and store it securely. WordPress only displays it once.
Use the WordPress username and generated password as
WP_API_USERNAME
and
WP_API_PASSWORD
in the remote proxy configuration. Application Passwords can be revoked independently from the user's profile.
HTTPS Enforcement
​
Use HTTPS for remote HTTP connections so credentials are encrypted in transit. Local STDIO connections authenticate through WP-CLI using the configured
--user
and do not require an Application Password.
Permission Validation
​
The MCP Adapter authenticates requests as the WordPress user associated with the Application Password. The default server requires an authenticated user with the
read
capability, and each WooCommerce ability also enforces its own permission callback. Use a dedicated WordPress user with only the capabilities the MCP client needs.
Server Endpoint
​
WooCommerce abilities are available through the WordPress MCP Adapter's default server:
https://yourstore.com/wp-json/mcp/mcp-adapter-default-server
The WooCommerce-specific
/wp-json/woocommerce/mcp
endpoint was removed in WooCommerce 11.3. See
Removed in WooCommerce 11.3
.
Connecting to the MCP Server
​
Choose a connection method based on where the WordPress site is running. For a detailed overview and application-specific instructions, see
Connecting AI applications
and the
wordpress/mcp-adaptor repository
.
Local Sites Using STDIO
​
For a local WordPress installation, MCP clients can connect directly through the MCP Adapter's WP-CLI command. The client needs access to the WordPress files and a working WP-CLI installation.
JSON Configuration
​
Add the following server to your MCP client configuration. Replace the WordPress path and user with values from your local environment:
{
"mcpServers"
:
{
"woocommerce_store"
:
{
"command"
:
"wp"
,
"args"
:
[
"--path=/path/to/your/wordpress/site"
,
"mcp-adapter"
,
"serve"
,
"--server=mcp-adapter-default-server"
,
"--user=admin"
]
}
}
}
Claude Desktop, Claude Code, and Cursor use the
mcpServers
property shown above. For VS Code, use
servers
instead.
Command-Line Configuration
​
Claude Code users can add the same server from the command line:
claude mcp add woocommerce_store -- \
wp --path=/path/to/your/wordpress/site \
mcp-adapter serve \
--server=mcp-adapter-default-server \
--user=admin
You can verify the server directly with WP-CLI:
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}' | \
wp --path=/path/to/your/wordpress/site \
mcp-adapter serve \
--server=mcp-adapter-default-server \
--user=admin
Remote Sites Using HTTP
​
For a remote WordPress installation, use the
@automattic/mcp-wordpress-remote
proxy. The proxy translates the MCP client's local STDIO messages into HTTP requests to the WordPress MCP Adapter.
Before connecting:
Create or select a dedicated WordPress user with the minimum required capabilities.
Open the user's
Profile
screen and create a WordPress Application Password.
Confirm the site uses HTTPS and non-Plain permalinks.
JSON Configuration
​
Add the following server to your MCP client configuration. Replace the example URL, username, and Application Password:
{
"mcpServers"
:
{
"woocommerce_store"
:
{
"command"
:
"npx"
,
"args"
:
[
"-y"
,
"@automattic/mcp-wordpress-remote@latest"
]
,
"env"
:
{
"WP_API_URL"
:
"https://yourstore.com/wp-json/mcp/mcp-adapter-default-server"
,
"WP_API_USERNAME"
:
"your-username"
,
"WP_API_PASSWORD"
:
"your-application-password"
}
}
}
}
Claude Desktop, Claude Code, and Cursor use the
mcpServers
property shown above. For VS Code, use
servers
instead. Do not commit a configuration containing an Application Password to version control.
Command-Line Configuration
​
Claude Code users can add the remote server from the command line:
claude mcp add \
--env WP_API_URL=https://yourstore.com/wp-json/mcp/mcp-adapter-default-server \
--env WP_API_USERNAME=your-username \
--env WP_API_PASSWORD='your-application-password' \
woocommerce_store \
-- npx -y @automattic/mcp-wordpress-remote@latest
Troubleshooting
: For common setup issues with npx versions or SSL in local environments, see the
mcp-wordpress-remote troubleshooting guide
.
Discover WooCommerce Abilities
​
The default MCP server exposes three tools:
mcp-adapter-discover-abilities
,
mcp-adapter-get-ability-info
, and
mcp-adapter-execute-ability
. A
tools/list
response shows these adapter tools, not a separate tool for each WooCommerce ability. Use the discovery tool to list available abilities, then get an ability's schema before executing it.
For a local site, you can check discovery with WP-CLI:
echo '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"mcp-adapter-discover-abilities","arguments":{}}}' | \
wp --path=/path/to/your/wordpress/site \
mcp-adapter serve \
--server=mcp-adapter-default-server \
--user=admin
On a WooCommerce 11.3 site, the response should include abilities such as
woocommerce/products-query
and
woocommerce/order-notes-query
. Each ability checks permissions when it runs. See the
MCP Adapter default server guide
for the discovery and execution flow.
Background
​
The Model Context Protocol (MCP) is an open standard that enables AI applications to securely connect to external data sources and tools. Using MCP with WooCommerce relies on two core technologies:
WordPress Abilities API
- A standardized system for registering capabilities in WordPress, included in WordPress core
WordPress MCP Adapter
- The core MCP protocol implementation, installed as the
MCP Adapter plugin
This architecture allows WooCommerce to expose operations as MCP tools through the flexible WordPress Abilities system while maintaining existing security and permission models.
What's Available
​
WooCommerce registers purpose-built abilities for core store operations. These abilities are available through the WordPress Abilities API and can be surfaced through the shared WordPress MCP adapter.
Purpose-Built WooCommerce Abilities
​
Product Management
​
Query products with filtering and pagination
Create new products
Update existing products
Delete products
Order Management
​
Query orders with filtering and pagination
Query notes for an order (
woocommerce/order-notes-query
)
Update order status
Add order notes
All operations respect WooCommerce's existing permission system. MCP clients authenticate through the MCP Adapter as a WordPress user.
Removed in WooCommerce 11.3
​
WooCommerce 11.3 removed the deprecated WooCommerce MCP endpoint and everything that only existed to support it:
The
/wp-json/woocommerce/mcp
endpoint and its WooCommerce REST API key authentication (
X-MCP-API-Key
). Requests to the endpoint now return HTTP 410 with a JSON-RPC error that explains how to connect through the MCP Adapter.
The REST-derived product and order abilities (
woocommerce/products-list
,
woocommerce/orders-get
, and similar), along with the
woocommerce_mcp_include_ability
,
woocommerce_mcp_allow_insecure_transport
, and
woocommerce_check_rest_ability_permissions_for_method
filters and the
expose_in_deprecated_woocommerce_mcp
ability metadata.
Custom abilities registered by extensions or custom code that appeared in the removed endpoint don't carry over automatically. Before WooCommerce 10.9, the endpoint included abilities in the
woocommerce/
namespace; from 10.9, it included abilities with
expose_in_deprecated_woocommerce_mcp
set to
true
; and the
woocommerce_mcp_include_ability
filter could add or remove abilities in either version. The MCP Adapter's default server ignores all of these. It only exposes an ability when its
meta.mcp.public
is
true
(if
meta.mcp.public
is not set, the adapter falls back to the top-level
meta.public
). To keep a custom ability available to MCP clients, set that metadata as shown in
Adding Custom Abilities
.
To keep using WooCommerce with MCP, install the
MCP Adapter plugin
and connect your MCP client to its default server, as described in
Connecting to the MCP Server
. Stores that had the WooCommerce MCP feature enabled see an admin notice about the change.

Architecture
​
Data Flow Overview
​
The MCP integration uses a multi-layered architecture to bridge between MCP clients and WordPress:
AI Client (Claude, etc.)
↓ (MCP protocol over stdio/JSON-RPC)
Local MCP Proxy (mcp-wordpress-remote)
↓ (HTTP/HTTPS requests with authentication)
Remote WordPress MCP Server (mcp-adapter)
↓ (WordPress Abilities API)
WooCommerce Abilities
↓ (REST API calls or direct operations)
WooCommerce Core
Architecture Components
​
Local MCP Proxy
(
mcp-wordpress-remote
)
Runs locally on the developer's machine as a Node.js process
Converts MCP protocol messages to HTTP requests
Handles authentication header injection
Bridges the protocol gap between MCP clients and WordPress REST endpoints
Remote WordPress MCP Server
(
mcp-adapter
)
Is provided by the
MCP Adapter plugin
, which must be installed and active
Powers MCP tool discovery and execution for WordPress abilities
WordPress Abilities System
​
Provides a standardized way to register and execute capabilities
Acts as an abstraction layer between MCP tools and actual operations
Enables flexible implementation approaches (direct operations, REST bridging, and so on)
Core Components
​
Purpose-Built Domain Abilities
(
Domain
)
Provide WooCommerce product and order abilities backed by domain APIs
Use shared WordPress MCP adapter metadata (
mcp.public
and
mcp.type
) for MCP exposure
Keep the ability contract focused on agent-friendly store operations
Implementation Approach
​
WooCommerce implements its abilities as purpose-built domain abilities. These abilities use schemas and response shapes designed for agent workflows instead of automatically projecting every REST-shaped operation into MCP.
Extending MCP Capabilities
​
Third-party plugins can register additional abilities using the WordPress Abilities API. Abilities can be implemented in various ways, including direct operations, custom logic, REST endpoint bridging, or external integrations.

Development Example
​
For a complete working example, see the
WooCommerce MCP Ability Demo Plugin
. This demonstration plugin shows how third-party developers can:
Register custom abilities using the WordPress Abilities API
Define comprehensive input and output schemas
Implement proper permission handling
Integrate with MCP through the shared WordPress MCP adapter
The demo plugin creates a
woocommerce-demo/store-info
ability that retrieves store information and statistics, demonstrating the integration patterns for extending WooCommerce MCP capabilities while using a direct implementation approach rather than REST endpoint bridging.
Troubleshooting
​
Common Issues
​
MCP Server Not Available
​
Verify the MCP Adapter plugin is installed and active
Confirm the client connects to
/wp-json/mcp/mcp-adapter-default-server
, not the removed
/wp-json/woocommerce/mcp
endpoint
Authentication Failures
​
Confirm
WP_API_USERNAME
matches the WordPress user that created the Application Password
Confirm
WP_API_PASSWORD
contains an active Application Password, not the user's account password or a WooCommerce REST API key
Verify the WordPress user has the capabilities required by the ability
Ensure HTTPS is used for remote HTTP connections
Ability Not Found
​
Confirm the ability category is registered during
wp_abilities_api_categories_init
Confirm abilities are registered during
wp_abilities_api_init
Verify ability callbacks are accessible
Check
WooCommerce → Status → Logs
for entries with source
woocommerce-abilities
.
