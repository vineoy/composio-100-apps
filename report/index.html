What the data says, plainly:
  • OAuth2 dominates: 37 of 51 apps (73%) support it; API key is the next most common.
  • 31 of 51 apps are free self-serve for developers; 12 are gated (paid plan, admin approval, or partner/sales).
  • 27 apps already ship an official MCP server, 5 have community MCP - the rest is whitespace for agent toolkits.
  • Most common blocker: Admin / app-review approval (4 apps).
  • 12 easy wins: self-serve + documented API + no official MCP yet - build these toolkits first.
  • 6 apps need outreach or are blocked - business development, not engineering.
  • Composio already ships toolkits for 42 of 51; 9 are catalog whitespace.

4 · The agent — what was built, where a human was needed

Fully automated

  • Search, doc fetching, evidence saving (per-app checkpointed, resumable).
  • Structured extraction with a strict schema: "cite a URL for every claim; say unknown rather than guess."
  • Composio SDK: fetched their full 1,842-toolkit catalog to check existing coverage per app.
  • Loop A evidence grounding + schema checks; Loop B independent second pass + arbiter reconciliation.
  • All statistics, charts and this page (generated from data, zero hand-editing).

Where a human was needed

  • Judgment calls on gated apps — browser deep-checks of ambiguous pricing/auth pages (agent-driven browser, human-reviewed conclusions).
  • The 15-app stratified audit — a human checked our answers against real docs and marked right/wrong (results in §6).
  • Corrections — human-confirmed misses were applied to the final dataset and are badged in the matrix.
  • Free API keys — a human created the free Gemini + Composio accounts ($0, no card).

6 · Verification — how accuracy was proven and improved

Loop A · automated (100/100)

Every cited URL must exist in the saved evidence; claimed auth/MCP keywords must appear in the fetched docs; schema + enum validation. Flags feed the arbiter.

Loop B · independent agent pass (100/100)

Re-research with a different model (Gemini 3.6 Flash) and reordered prompt, blind to pass-1 answers. Field-by-field diff; disagreements settled by an arbiter reading the actual docs.

Loop C · browser deep-checks

A real browser visited ambiguous auth/pricing pages for the hardest apps (gated fintech, obscure tools); conclusions reviewed against what the pages actually show.

Loop D · human audit (15 apps)

Stratified sample across categories, weighted toward disputed/low-confidence rows. A human marked each field right/wrong against real docs; misses corrected and shown below.

7 · Process & limitations

How it was built

  • Assignment + 100-app list extracted programmatically from Notion's page API (no manual transcription).
  • Free-tier smoke tests before any bulk work; model availability issue found and fixed early (JSON-mode needed newer Gemini models).
  • Pass 1 → automated checks → independent pass 2 → arbiter → browser checks → human audit → analysis → this page. Every action timestamped in log.md.
  • Total cost: $0 — Gemini free tier, DuckDuckGo, Composio free plan (2 catalog calls), no hosting.

Honest limitations

  • Docs-only research: no paid accounts were created, so "gated" findings rest on public pricing/docs pages — which the assignment explicitly says is correct.
  • Pass 2 reuses the saved evidence (independence is at the reasoning level: different model + prompt); disputed fields triggered fresh evidence review by the arbiter.
  • API breadth is a rough bucket estimated from visible docs, not an endpoint count.
  • Obscure apps (e.g. Paygent Connect, iPayX, fanbasis) may have partner-only docs we cannot see; marked unknown/blocked with evidence rather than guessed.
  • Free-tier rate limits pace the run (~9 LLM req/min); the pipeline is resumable, so nothing is lost on interruption.
